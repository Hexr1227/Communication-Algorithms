### 系统平均吞吐量

观察窗口内所有用户实际发送量之和，除以总仿真时隙数，包括初始空闲、突发和恢复段。单位数据单位/时隙，不是包/时隙，也不是程序运行秒数。这里统计部分发送的数据，不只统计完成包。若需要物理bit/s，必须另外定义每数据单位对应多少bit及每时隙秒数。

### Jain公平性

J=(sum(x))^2/(U*sum(x_i^2))，其中x为每用户累计实际发送量。所有用户观察时长相同，使用每用户平均吞吐量会得到相同指数。包括零吞吐用户；至少一个用户非零时范围[1/U,1]。全零为0/0，本课程返回None，不宣称全部饿死仍公平。

公平性衡量的是吞吐分配均匀性，不能直接证明等待公平；用户业务需求不同时，也不能把均匀吞吐自动等同于服务合理。来源原文核实仍待完成，结束本课前记录核实范围。

### 完成时延与未完成包

统计mean/p95/max，只对已完成样本。p95固定采用最近秩法：升序后第ceil(0.95*n)个数；Python下标需减1。它与插值分位数可能不同，报告中写明。不要修改传入列表排序。

同时报告completed、pending、completion_ratio。到达包数是arrivals中正数单元格的数量，不是sum(arrivals)，因为每个正数表示一个包的大小。pending是包数，remaining是数据量，部分发送的包仍算一个未完成包。无完成时的时延统计、无到达时的完成比例均用None，不假装为0。

## 手算

4个时隙，两个用户累计发送[6,2]：先算系统平均吞吐量。再算Jain指数。若delays=[1,2,2,5]、共到达6个包，计算完成数、未完成数、完成比例、平均时延、p95、max。
