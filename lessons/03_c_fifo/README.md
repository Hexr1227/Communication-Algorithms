## 所需知识

C 的数组参数传递地址，函数不会自动知道数组长度；slots 是本课统一数组长度。const 指针限制通过该指针修改输入。size_t 用于索引和长度；uint32_t 用于非负包大小和容量，uint64_t 用于积压总量。无符号数仍可能溢出，不能当成无限大的 Python int。

本课所有内存由调用者提供，函数借用：不要 free 输入或输出，也不要返回局部变量地址。scratch 与 scratch_remaining 是可写工作数组，分别用于包到达时隙与剩余大小，长度均为 slots。你自己设计索引和 FIFO 状态。每个时隙最多到达一个包，因此这些数组足够保存整场仿真所有包；这是容量规划，不是无线服务容量。

NULL 表示没有可访问的地址；非空仿真必须校验所需指针。通过输出指针返回标量时，需要理解“指针本身”和“它指向的值”的区别。若这些概念不熟，先 fork 到内容消化线：C 数组、指针、const 和内存所有权。

## 本课模型与接口

延续先服务旧队列、后到达、允许部分发送。为控制第一次 C 作业规模，arrivals[t] 是一个包的大小；0 表示本时隙无包，不支持同时到达多个包。输入/输出要求见 student.h。只编辑 student.c 和 reflection.md；接口与验收文件由助手维护。调用者必须提供长度足够且互不重叠的缓冲区，C 无法由裸指针验证实际分配长度。

served[t] 为实际服务数据单位；backlog[t] 为到达后的积压；delays 按完成顺序记录完成时隙减到达时隙；completed_count 给出有效时延数；remaining 为最终积压。空输入应返回成功、完成数和剩余量为 0。溢出返回 2；非法参数返回 1；失败时输出不用于分析。

## 手算

capacities = [0,2,2,3]，arrivals = [3,0,2,0]。
时隙 0 后积压 3；时隙 1 发 2；时隙 2 发完旧包的 1，随后新包 2 到达；时隙 3 发完 2。请自己写出 served、backlog 和两个包的时延，再写代码。
