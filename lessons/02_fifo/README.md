# 第二课：FIFO 包、部分发送与时延

## 课前回顾

第一课已通过：发送受容量与旧队列限制，先服务后到达，数据量守恒。进入本课前用一句话说明：只有发送量和队列总量，能否知道每个包等了多久？

## 所需知识

FIFO（先进先出）表示早到的包先服务，同一时隙到达时按输入列表顺序。包大小可不同，一个包允许分多个时隙发送；只有全部发送完才记录完成时延。当前包未完成时，后面的包不能先发送。一个时隙也可能发完多个包，容量是数据单位，不是包数。

需要掌握 Python 列表/元组/字典、循环、状态记录和异常；可自行选择队列表示，不规定使用何种容器。每个包需要可识别的编号、到达时隙、原始大小与剩余量。编号从 0 开始，按到达顺序递增。时间仍是模拟时隙，不需要 sleep。

延续第一课：时隙 t 先服务旧包，再加入 arrivals[t]。包在时隙 a 末到达，在时隙 d 发完，时延为 d-a 个时隙。这个定义包含等待与发送过程；项目暂称排队完成时延，不单独计算纯等待时长。未完成的包不记作完成包，也不能被当作时延为零。

## 作业接口

仅编辑 student.py 与 reflection.md。函数 simulate_fifo(capacities, arrivals) 的校验要求见框架。

返回 dict，恰好包含四项：

- served：每时隙实际发送的数据量列表。
- backlog：每时隙服务及到达后的剩余数据总量列表。
- completed：按完成顺序的元组列表；每项 (包编号, 到达时隙, 完成时隙, 完成时延)。
- pending：模拟结束时的 FIFO 元组列表；每项 (包编号, 到达时隙, 原始大小, 剩余大小)。

输入长度为零时四项均为空列表。校验应覆盖完整输入，输入不能被修改。无限缓冲区，不丢包、不重传。

## 手算例子

capacities = [0, 2, 2, 3]
arrivals = [[3, 1], [], [2], []]

时隙 0：无旧包，发送 0；包 0（大小 3）和包 1（大小 1）到达，积压 4。
时隙 1：包 0 发送 2，尚余 1；积压 2，无包完成。
时隙 2：包 0 和包 1 各发送 1，都完成，时延均为 2；随后包 2 到达，积压 2。
时隙 3：包 2 发送 2，完成，时延为 1；积压 0。剩余容量不产生虚构数据。

因此 served 为 [0,2,2,2]，backlog 为 [4,2,2,0]。请自己写出 completed 和 pending，并以此检查你的实现。
