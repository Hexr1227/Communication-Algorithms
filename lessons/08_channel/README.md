## 所需知识与模型

Python生成场景，C推进队列与调度。每用户状态为G（好）或B（差），映射成固定容量。例如G对应4、B对应1，单位均为数据单位/时隙。这是抽象的有效服务能力，不是信噪比、比特率或完整物理层模型。

两状态马尔可夫假设：给定当前状态，下一状态的概率不再依赖更早历史。用户之间独立抽样，转移概率固定；未模拟共同遮挡、用户移动或编码误码。

- G状态：以p_good_to_bad变成B，否则保持G。
- B状态：以p_bad_to_good变成G，否则保持B。
- 随机数严格小于对应阈值才切换，每次转移只判断一次。

初始状态显式传入，不默认处于稳态。概率0允许状态不变，概率1允许每次切换。因此本课模型也可表达交替状态，不能断言所有参数都使相邻时刻正相关。

## 时间与抽样契约

1. 时隙0容量由初始状态决定，不预先转移。
2. 此后每到下一时隙，先根据上一状态转移一次，再记录新状态对应容量。
3. 转移按时间优先、用户其次抽样；只用一个局部random.Random(seed)。
4. T个时隙、U个用户恰好抽(T-1)*U次，概率端点也抽样；T=1不抽样。
5. 各用户持久保存自己的状态；不修改传入的初始状态列表，每行列表独立。

全部参数、类型和范围见student.py。initial_good中的True表示G，False表示B。容量允许相等、允许均为0，方便验证边界。只编辑student.py与reflection.md，不修改C内核。
