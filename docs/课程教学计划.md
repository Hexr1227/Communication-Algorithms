# 实践课程教学计划

目标：学生亲手完成 Python+C 的单小区、多用户下行调度仿真，研究突发业务下的尾部等待与吞吐量取舍。原两份架构文档是历史设计参考；执行方式以 AGENT.md 和本计划为准。技术假设会在各课明确，研究结论由实验决定。

## 日程与验收

建议每天 4–6 小时，其中回顾/知识约 1 小时，独立编码 2–3 小时，测试排错及讲解 1–2 小时。按 14–18 天规划，10 天时保留核心仿真、传统对照与可信实验，推迟可选拓展；Python+C 分工不删。进度依实际验收调整，不按日历强行通过。

每课统一格式：课前回顾 → 所需知识 → 手算 → 接口框架 → 学生实现 → 自动测试 → 学生解释 → 学习记录。完整代码只由学生编写。后续框架和测试在进入该课时准备，不预发全套答案。

## 全项目测试策略

测试由助手编写，学生实现。分别覆盖模型契约、手算确定样例、非法输入、守恒性质、C 内存与边界、跨语言一致性、算法行为、指标口径和可复現实验。性能基准不代替正确性。测试不得嵌入完整参考实现，也不隐藏答案模块。每课只认已经运行过的测试结果。

## 研究材料门槛

第 08–10 课核对公开文献/标准中的信道假设、PF/MaxWeight/等待感知算法和指标定义。记录来源链接/DOI、查阅日期、支持内容、与本项目差异。没有一致的实验条件不直接比较论文数值。使用独立测试种子，最终测试前锁定参数。

## 最终完成标准

学生亲手写所有项目主体；每课代码验收和内容验收均有记录。项目提供可编译 C 核心、Python 实验入口、可复现输入、传统对照、经过验证的方法或有价值的失败分析、指标和图表、运行耗时和明确局限。能独立从问题讲到代码与结果。RL、移动、多小区不属当前必做范围。
